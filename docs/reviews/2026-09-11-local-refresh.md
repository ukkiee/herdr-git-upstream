# 생성 팝업과 로컬 Git 변경 갱신 검증

2026-09-11. macOS darwin/arm64, Apple M5 Pro, Go 1.27.1, Git 2.55.0,
herdr 0.9.0에서 확인했다.

## 관찰 결과

| 대상 | 확인한 동작 |
| --- | --- |
| 브랜치 입력 | 좌우 커서 이동, 중간 삽입·삭제, 긴 이름에서 커서 주변 표시 |
| 기준 검색 | 1,201개 후보에서 부분 문자열 검색, 화살표 선택, 확정·취소, 비동기 후보 추가 중 선택 유지 |
| 경고 | 줄바꿈, F1 전체 메시지와 스크롤, 메시지 닫기에서 생성이 실행되지 않음 |
| 로컬 pull | 수정 전에는 다음 60초 회차 전까지 `↓1`이 남는 실패를 재현. 수정 후 실제 pull 뒤 4초 이내 토큰 해제를 확인 |
| 갱신 경쟁·실패 | 일반 회차가 막혀 있어도 로컬 변경 보고, 뒤늦은 회차의 예전 HEAD 재보고 방지, 보고 실패 후 새 Git 변경 없이 재시도 |

화면은 모델·렌더링 시험과 실제 실행 파일의 64×18, 62×16, 32×12 PTY로 확인했다.
Git 시험은 임시 저장소와 로컬 bare 원격을 사용했다. PTY 및 데몬 회귀 시험에서 외부 herdr CLI만
대체했으며 실제 사용자 저장소에서 pull하거나 worktree를 생성·삭제하지 않았다.

## 유휴 감지 비용

`BenchmarkPollLocalUnchanged27Worktrees1200Refs`는 1,200개 loose ref를 공유하는
27개 checkout의 메타데이터를 구성한다. 아래 명령을 3회 측정했다.

```sh
go test ./internal/daemon -run '^$' \
  -bench BenchmarkPollLocalUnchanged27Worktrees1200Refs -benchtime=2s -count=3
```

검사 1회당 4.68ms, 3.79ms, 3.77ms였고 약 996KB, 6,341회 할당이었다.
1초 주기 검사에서 같은 저장소의 공유 참조는 한 번만 읽는다. 변경이 없으면 Git 명령,
네트워크 요청, herdr 메타데이터 보고는 실행하지 않는다.

이 수치는 위 임시 자료와 로컬 디스크에서의 유휴 검사 비용이다. 변경 후 Git 판정·보고 비용이나
다른 디스크·저장소 수에서의 성능을 나타내지 않는다. 원격 fetch의 기본 60초 주기,
같은 참조의 120초 스로틀, 최대 4개 fetch 동시 실행은 유지했다.

## 완료한 검사와 적용 범위

- `go test -race ./...`, `go vet ./...`, gofmt, `git diff --check` 통과.
- linux/darwin/windows × amd64/arm64 여섯 대상 교차 빌드 통과. Linux·Windows 실행은 미검증.
- `sh scripts/build.sh`로 연결된 실행 파일 갱신.
- 기존 데몬의 정상 종료와 새 실행 파일 기동을 로그·프로세스 경로·잠금·`status`로 확인.
  새 프로세스는 `daemon_alive=true`, `interval=1m0s`, `throttle=2m0s`였다.

실제 사용자가 pull한 뒤 화면이 바뀌는 마지막 시각 확인은 아직 하지 않았다. `gone`과
`sync_stale`은 플러그인의 원격 확인 기록을 계속 사용하므로 로컬 변경 감지만으로 사라지지 않는다.

## 후속 생성 팝업 배치 수정

사용자 화면의 `[main-2 ]` 공백과 전체 폭 선택 목록을 렌더링 회귀 시험으로 재현했다.
이름 끝에서는 닫는 괄호를 커서로 표시하고, 포커스가 없으면 실제 이름만 표시한다.
접힌 기준 필드는 이름 길이에 맞추며, 펼친 목록은 최대 38칸 폭·4개 후보로 줄였다.
검색은 위쪽 테두리, 개수는 아래쪽 테두리에 합쳤다. 강조한 후보의 종류·상태는 아래 한 줄에
표시하며, 긴 이름은 중간을 줄여 서로 다른 끝부분을 남긴다.

수정 후 전체 `go test -race ./...`, vet, gofmt, diff 검사와 여섯 대상 교차 빌드를 다시 통과했다.
실제 실행 파일을 64×18, 62×16, 32×12 PTY에서 실행해 1,201개 후보 검색·선택·취소,
공백 없는 이름·중간 편집·커서, 경고·F1 전체 보기, 터미널 복원을 확인했다.
외부 herdr CLI는 앞선 시험과 같은 경계로 대체했다. 자료는
`/private/tmp/hgu-create-pty-6vqeu2k_`의 `*-name.txt`, `*-open.txt`, `*-search.txt`,
`*-warning.txt`, `*-message.txt`와 ANSI 기록에 남겼다.

연결된 실행 파일을 `sh scripts/build.sh`로 갱신했다. 이미 열린 생성 팝업은 닫고 다시 열어야
새 배치가 적용된다. 실제 herdr 팝업의 최종 시각 확인은 사용자에게 남아 있다.

## 검색 일치 부분 강조

검색 결과의 일치 글자에 청록색과 굵기를 적용했다. 선택 행의 반전 표시는 유지한다.
대소문자를 바꿔 검색해도 브랜치 이름의 원래 표기를 보존하며, 한글·반복·겹치는 일치를 처리한다.
말줄임 전에 원문에서 범위를 구하므로 경계에 걸친 일치도 보이는 글자에만 강조가 적용된다.
말줄임표는 강조하지 않으며, 검색어가 없거나 목록을 닫으면 강조를 제거한다.

렌더링 시험의 수정 전 실패와 수정 후 통과, 전체 `go test -race ./...`, vet, gofmt,
`git diff --check`를 확인했다. 새 빌드를 64×18, 62×16, 32×12 PTY에서 실행해 1,201개 후보의
검색·선택·취소와 실제 ANSI 출력의 일치 강조·선택 행 유지·선택 후 꾸밈 해제를 확인했다.
자료는 `/private/tmp/hgu-create-pty-8ioovetr`의 `*-highlight.ansi`와 전체 ANSI 기록에 있다.
외부 herdr CLI는 시험 경계로 대체했다. 연결된 실행 파일도 다시 빌드했다.
