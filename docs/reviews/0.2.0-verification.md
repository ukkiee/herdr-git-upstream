## Platform

연결된 worktree에서 아직 열지 않은 형제 worktree에 Enter를 누르면 herdr가 source를 거절했다.
본 체크아웃을 `worktree open --cwd`로 전달하도록 고쳤고 실제 argv 및 연결된 worktree에서
시작하는 controller 회귀를 독립적으로 확인했다. 남은 material finding 0건.

## 연결 검증

A~D 검토·커밋 이후 herdr 0.9.0에 플러그인을 link하고 0.2.0 바이너리를 빌드했다.
`plugin list` 활성화, `status`의 버전·데몬 생존, `config check` 및 플러그인 로그를 확인했다.

실측에서 발견한 두 차이는 수정했다. popup 크기는 문자열 `"64"`/`"18"`이 아니라 정수 셀 수여야
하므로 manifest를 고쳤다. `plugin link`는 build 훅을 실행하지 않으므로 양쪽 README에 선행 빌드를
추가했다. herdr 소스와 실제 typed manifest로 독립 검토했다.

| 확인 대상 | 결과 |
| --- | --- |
| 기본 placement | 옵션 없는 열기가 manifest의 popup을 따름. 사용자 스크린샷으로 실제 popup 표시 확인 |
| 드롭다운 | 사용자 피드백에 따라 Base를 접힌 필드로 변경. Tab→Enter 열기, 화살표 임시 강조, Enter 확정, Esc 메뉴 닫기, Ctrl-C 취소. Name Enter만 생성 |
| 원격 기준 생성 | 임시 저장소에서 origin/main을 선택해 생성. 선택한 원격 HEAD와 일치하고 새 브랜치 upstream은 설정되지 않음 |
| worktree 토큰 | 임시 linked worktree의 API 정보에서 `behind=↓1`, `merged=merged` 보고 확인. 설정 적용 후 사용자가 실제 mfe 사이드바 토큰 표시 확인 |
| 안전 삭제 | 임시 저장소에서 safe만 삭제되고 브랜치는 보존됨. dirty·locked는 거절. 실제 저장소 삭제는 실행하지 않음 |
| 실제 mfe 판정 | 당시 27개 worktree 중 4개 safe. 현재 mergeTarget은 미설정. 아래쪽 행까지 조회했으며 설정·삭제는 하지 않음 |

드롭다운의 Standards·Spec·플랫폼 독립 검토는 각각 남은 material finding 0건이다.
후보가 하나인 경우와 62×16 화면의 네 종류 후보, 비동기 기본 브랜치 삽입 중 강조·확정 기준·직접
입력한 이름 보존을 회귀 및 독립 임시 시험으로 확인했다. 변경 후 전체 `go test -race ./...`, vet,
gofmt, 여섯 대상 빌드와 typed 크기/TOML 검사를 다시 통과했다. 같은 TUI를 실제 herdr tab으로
열어 드롭다운 열기·취소·확정과 원격 기준 생성도 재검증했다.

실측 자료는 `/private/tmp/hgu-live-verify-n2xvfp25`에 남겼다. `dropdown-open.txt`,
`dropdown-cancel.txt`, `dropdown-selected.txt`, `dropdown-created.json`, `worktrees-before.txt`,
`dirty-refusal.txt`, `locked-refusal.txt`, `mfe-worktrees.txt` 및 `setup.txt`가 해당 근거다.

초기 연결 검증에서는 파일 해시로 사용자 설정 무변경을 확인했다. 이후 사용자가 설정 추가는
에이전트에게 맡기고 reload는 직접 실행하겠다고 요청했다. 기존 config.toml을 백업하고
사이드바 토큰 여섯 개와 `prefix+shift+u` worktrees 키를 추가했으며 기존 설정은 보존했다.
사용자가 실행한 `config check`는 `config: ok`, `server reload-config`는
`status=applied`, `diagnostics=[]`를 반환했다. 후속 status에서도 `daemon_alive`,
`sidebar_configured`, `key_bound`가 모두 true이며 mfe의 `behind=↓1`, `merged=merged`
메타데이터 보고를 확인했다. 사용자가 mfe 사이드바 브랜치 줄의 토큰도 보인다고 확인했다.

들여쓴 linked worktree 행 자체의 시각 확인은 별도로 하지 않았으며, 위 임시 저장소 시험은
그 worktree에 대한 API 토큰 보고를 확인한 것이다. mfe의 `origin/widget-studio/dev`
통합 대상 추가와 실제 worktree 삭제는 사용자가 결정한다.
Windows 실행과 최소 Git 2.31 실행은 미실측 상태다.
