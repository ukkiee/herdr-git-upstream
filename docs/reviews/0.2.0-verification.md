## 팝업 저장소 선택 회귀 수정

herdr의 popup cwd는 플러그인 뿌리이며 호출 workspace는 `HERDR_PLUGIN_CONTEXT_JSON`에 있다.
화면 진입점이 JSON을 무시해 플러그인 저장소의 worktree 1개를 읽는 오류를 수정했다.

## mfe 통합 기준 적용 전 비교

2026-09-11 인계의 남은 저장소별 설정 항목을 확인했다. `git-upstream.mergeTarget`은 비어 있고,
로컬 `origin/HEAD`는 `origin/main`을 가리킨다. `origin/widget-studio/dev` 추적 참조는 존재한다.
현재 인증의 `git ls-remote`는 `Repository not found`로 실패했다. 계정 설정을 변경하지 않고
이미 있는 로컬 추적 참조를 기준으로 비교했으며, 최신 원격 브랜치 삭제 여부는 확인하지 않았다.

HEAD `765b6f1`의 독립 임시 복사본에서 실제 수집·판정 함수를 호출했다. 추가 기준은 실행 중인
프로세스의 Git 설정 환경변수로만 주입했고, 판정 캐시와 merge-tree 객체는 임시 디렉터리에 썼다.
비교 도중 각 worktree HEAD가 같은지도 확인했다. 실제 Git 설정과 worktree에는 변경을 적용하지 않았다.

| 로컬 판정 | 기존 기준 | `origin/widget-studio/dev` 추가 |
| --- | --- | --- |
| safe | 4 | 6 |
| keep | 19 | 17 |
| review | 3 | 3 |
| blocked | 1 | 1 |

`fix/widget-studio-prefetch-barrel-chunk-cycle`와 `widget-studio/design-qa-2` 두 행이
`keep / no tracking ref`에서 `safe / merged`로 바뀐다. 총 27개이며 실제 삭제는 실행하지 않았다.
원본 설정의 `mergeTarget`은 비교 후에도 비어 있다. 적용할 명령은 다음과 같으며 사용자 결정 대기다.

```sh
git -C /Users/ukyi/workspace/mfe config --local --add git-upstream.mergeTarget origin/widget-studio/dev
```

비교 근거는 `/private/tmp/hgu-mfe-preview-5pabb0xy/comparison.json`과 같은 복사본의
`internal/worktreeui/live_preview_test.go`에 있다. 실행 결과는 PASS(7.316초)다.

## 생성 팝업 전체 브랜치와 이름 편집

2026-09-11 사용자가 `Ctrl+A → Shift+I` 시험 후 기준 브랜치 전체 목록과 이름 끝에서의 편집을
요청했다. 현재·upstream·기본·통합 후보만 모으던 계약을 바꿔 나머지 로컬 브랜치와 알려진
원격 추적 브랜치도 표시한다. 추천 후보가 먼저이며 그 뒤 각 종류를 이름순으로 나열한다.
전체 참조로 중복을 제거하고, 드롭다운에 현재 위치/전체 개수를 표시한다.

원격 매핑은 참조마다 Git을 실행하지 않고, 원격별 fetch 사양을 한 번 읽어 해석한다.
별명·PR/tag 참조는 제외한다. 독립 검토에서 기본 wildcard 뒤의 PR 사양이 섞이는 경우와
`refs/remotes/cache/*`처럼 원격 이름과 다른 목적지를 빠뜨리는 경우를 각각 재현했다.
기존 non-branch 제외 규칙을 재사용하고 실제 목적지 사양을 먼저 역매핑해 두 RED를 GREEN으로 고쳤다.

추가 원격 후보는 기준으로 확정할 때만 좁게 fetch한다. 로컬 기준은 fetch 없이 바로 사용한다.
임시 원격의 최신 커밋으로 추가 원격 후보를 생성하고 upstream이 해제되는 것, 다른 로컬 기준의
커밋이 생성 훅으로 옮겨지지 않는 것도 확인했다. 실제 사용자 저장소에서 생성·삭제하지 않았다.

이름 전체 선택을 없애고 끝에 커서를 표시한다. 입력은 뒤에 붙고 Backspace는 마지막 Unicode
문자를 하나 지운다. 긴 이름은 끝과 커서를 보이게 한다. 입력 덮어쓰기·전체 삭제를 기존 키 처리
